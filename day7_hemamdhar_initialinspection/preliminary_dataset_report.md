## 4. Expected Inspection Outputs

Run `initial_inspection.ipynb` after the archive is populated. It will generate the following under `inspection_outputs/`:

- `inventory.json`: file, image, label, video, and configuration counts per dataset.
- `label_records.json`: parsed label rows, matching-image status, sequence ID, frame marker, and validation errors.
- `class_counts.json`: object-instance counts by dataset and class ID.
- `image_stats.json`: image format, dimensions, mode, and open/read errors when Pillow is available.
- `exact_duplicates.json`: groups of exact image duplicates identified by file size and SHA-256.

The notebook does not perform cleaning, resizing, enhancement, relabeling, deduplication, or deletion.

- The datasets have different class vocabularies and should not be merged without an explicit mapping.

These values are documentation-based expectations, not results generated by the Day 7 notebook.

## 7. Preliminary Risks

1. **Archive access risk:** the raw folders are not locally available until the Drive download is completed.
2. **Temporal leakage risk:** sequential frames must be grouped by source video or sequence before train/validation/test evaluation.
3. **Class-space risk:** classes across the three exports may have different meanings despite similar names.
4. **Tracking limitation:** frame-level detection labels do not establish persistent object identity.
5. **Metadata limitation:** camera, location, water condition, depth, and lighting fields may be unavailable.
6. **Quality risk:** class imbalance, empty labels, duplicate frames, corrupted images, and invalid boxes must be measured rather than assumed absent.

## 8. Data-Readiness Decision

**Current decision: Not ready for irreversible preprocessing or final model evaluation.**

The project can proceed to raw archive population and read-only inspection. Modelling should wait until the notebook confirms:

- all required folders and image-label pairs are present;
- labels parse correctly and class mappings are verified;
- invalid or unreadable files are documented;
- class and target coverage is known;
- duplicate and source-sequence risks are measured;
- leakage-safe split manifests are created and reviewed.
